Emerging Trends

The primary focus this week is the finalization of the WordPress 7.2 release cycle, scheduled for December 8, 2026. Development is currently in the Release Candidate (RC) phase, with RC1 already available for testing (WordPress 7.2 RC1).

Key technical trends include:

  • PHP 8.6 Readiness: WordPress core is being tested against PHP 8.6. While the minimum supported version remains 7.4, WordPress 7.2 is confirmed as fully compatible with 8.6 (WordPress and PHP 8.6).
  • Client-Side Media Processing: Significant expansion of browser-based image resizing and format conversion across the Media Library grid, "Add New Media File" screen, and media modal (WordPress 7.2 Field Guide).
  • jQuery 4 Roadmap: WordPress 7.2 will ship with jQuery Migrate 3.6.0 to identify deprecated code. The roadmap targets a full update to jQuery 4 in version 7.3, with a planned default disabling of jQuery Migrate by the end of 2027 (Preparing for jQuery 4 with WordPress 7.2).
  • Abilities API Evolution: A new "core-first" development workflow is being established for WordPress 7.3 abilities, where features are developed in core first before being synchronized to the shared package (AI Contributor Weekly Summary).

Developer Implications

Freelance and agency developers should note the following technical changes for upcoming projects:

  • Block Editor & Styling: Developers must rename the __experimentalGroup prop to group in InspectorControls to prevent controls from rendering in the default group (Miscellaneous Editor Changes in WordPress 7.2). Additionally, a new public API now allows for reading and updating block style attributes for specific viewport and pseudo states (API for style state-aware block styling controls).
  • REST API Adjustments: Revision and autosave responses will now only include revisioned meta keys. Developers needing to include non-revisioned keys must now use the revisions_enabled constant or the wp_post_revision_meta_keys filter (REST API changes in WordPress 7.2).
  • Interactivity API: The new data-wp-html directive requires the use of asDangerousHTML() to render HTML from the store (Changes to the Interactivity API in WordPress 7.2).
  • Permissions: The Abilities API now includes a required_capabilities argument. Developers should use this for global requirements and reserve permission_callback for checks requiring specific input data (Abilities API updates in WordPress 7.2).
  • Security & Maintenance: Version 7.1.5 addressed several vulnerabilities, including SQL injections in WP_Meta_Query and unauthenticated RCE via Template Part block attributes. Ensure all active sites are updated to at least 7.1.5 before the 7.2 release (WordPress 7.1.5 Release).
  • Tooling: The WordPress Contributor Toolkit 2.1.0 beta now supports Xdebug step debugging in the Playground environment, which can be configured for VS Code, Cursor, PhpStorm, and Zed (Call for testing: Xdebug in the WordPress Contributor Toolkit 2.1.0 beta).
